# LangQuest — Flutter learner app

The Flutter rewrite of the learner app (`apps/mobile` is the Expo app it replaces). It runs **offline**: it teaches
the shared draft curriculum bundled with the app and keeps the learner's progress on the device. When a backend is
configured, an optional account keeps courses and completed missions in step across devices
([Account](#account-optional-sign-in-and-sync)).

## Run

Flutter **3.47.7** (Dart 3.13.5), the version in `.metadata`.

```bash
cd apps/mobile_flutter
flutter pub get
flutter run                     # a connected device or simulator
flutter run -d chrome           # web
```

```bash
flutter analyze                 # expect: No issues found
flutter test                    # VM: content, learn plans, practice sessions, games, scheduler, state, widget flows
flutter test --platform chrome test/srs_test.dart   # the hashing/scheduler port compiled to JavaScript
flutter build web --release
```

## Web app (phone-sized) and its deployment

The web build is the same app, laid out for a phone: on a phone browser it fills the screen; in a wider window
(a computer or a tablet) it is shown as a centered phone (`lib/core/layout/phone_frame.dart`), and a mouse can drag
lists and card pages like a finger. Progress is kept in the browser's local storage. After one visit it also opens
offline (airplane mode, or from the home screen): `web/sw.js` serves the files from its cache when the network fails
(network first, so a redeploy shows on the next load; same-origin files only — the account API is never cached). The device voice is the
browser's speech synthesis, with the same exact-locale rule as on phones. On their own lines the learner can record themselves
(MediaRecorder; the browser asks for the microphone the first time, and only on https or localhost) and hear the take next to
the reference voice; the take stays in memory and is never uploaded.

First visit: about 4 MB over the wire (the CanvasKit engine, the app, its fonts and content), then served from the
service worker's cache. Of the content, start-up reads only the catalog and what every course shares (470 KB, about
60 KB compressed, most of it `voices.json`) plus the chapters of the learner's own courses: each course's chapters are a file of their own
(`assets/content/chapters/<trackId>.json`, 7–20 KB compressed), fetched when the learner opens a course and kept by the
service worker like every other file (`lib/core/content/content_bundle.dart`). Offline, the web app has the courses
it has fetched; the phone builds have every course on the device. The web engine downloads every font in
`assets/FontManifest.json` at start-up, so the image build prunes the icon package's unused weight variants
(`tool/prune_web_fonts.dart`, about 1.4 MB); run it after a local `flutter build web` too:
`dart tool/prune_web_fonts.dart build/web`.

CI checks the compiled app too: after building and serving the root image, `tool/web_smoke.cjs` drives it in Chromium
(first run → a lesson → record yourself with a fake microphone → Settings › Display → reload) and fails on any page
error — the Dart VM tests cannot see what dart2js does (it once broke recording while every VM test passed). It also
fails when a first visit fetches a course's chapters, or when opening a course or reloading fetches any course but the
one opened or the learner's.

The repository's root `Dockerfile` builds it (Flutter 3.47.7, pinned to its release commit) and serves the files with
Caddy on `$PORT` (default 8080, what the Infra Tayoo hosted app checks); `deploy/Caddyfile` sends `no-cache` so a redeploy shows on the next load. It reads no
variables: nothing from the host's environment is built into the files served. CI's `web-image` job builds the image
and checks that it serves the app.

```bash
docker build -t langquest-web .                      # from the repository root
docker run --rm -p 8080:8080 langquest-web           # http://localhost:8080
```

On Infra Tayoo (instance `languest`), the hosted app builds `master` with this image and health-checks
`0.0.0.0:8080`: `infra-tayoo status` shows the source and the app URL, `infra-tayoo deploy` deploys `master`'s latest
commit (the `infra-tayoo` CLI comes from the Infra Tayoo portal; its key must never be committed or printed).

Fonts: Inter and Outfit cover the interface; small Noto Sans subsets (`assets/fonts/scripts/`, 428 KB in all) cover
the other scripts the bundle uses (Japanese, Arabic, and the Chinese, Korean, Hebrew and Devanagari course names).
Without them the web engine downloads fallback fonts from `fonts.gstatic.com` and picks Chinese or Japanese kanji
forms by the browser's language. A phrase or course name puts its own script's font first (`core/theme/script_fonts.dart`),
so Japanese is drawn with Japanese forms everywhere. `test/script_fonts_test.dart` reads the subsets' character maps
and fails when the bundle uses a character they lack; then regenerate them (Python with fonttools, network access):

```bash
python3 -m venv /tmp/fonts-venv && /tmp/fonts-venv/bin/pip install fonttools==4.68.0
/tmp/fonts-venv/bin/python tool/subset_fonts.py     # from apps/mobile_flutter
```

## Account (optional): sign-in and sync

Without a backend the app is offline: progress lives on the device and nothing about accounts is shown. With one
(Settings › Account, shown only while the API answers `/healthz`), a learner signs in with email and password
(Supabase auth) and the app keeps the account in step with the device (`lib/core/backend/`):

| Synced | How |
|---|---|
| Courses | Enrolled here → `POST /v1/me/enrollments`; enrolled in the account → added here (archived ones are not). One active source per track on the server: a second instruction language of the same track stays on the device and is named in Settings. |
| Completed missions | Done here → `GET /v1/missions/:id` + attempt + evaluate. Steps built on the learner's own lines are claimed `success`, the others `unclear`: the server records the mission as completed for the path and credits nothing it has no evidence for. Done in the account → their stops are marked done here (read from the learner's own `mission_progress` rows), so the path continues on any device. |
| Not synced | Practice XP and the review schedule stay with the device that earned them. The server pays mission XP and creates review cards only for steps it holds evidence for: a take it checked itself (below) is that evidence for the mission's speaking steps, so a mission whose replies were checked while signed in is credited on the server when it syncs. |
| Speech check | Signed in, on a course whose capability snapshot (`GET /v1/me` → `capabilities.pronunciationScoring.mode`) is not `none` (`lib/core/backend/speech_check.dart`): each take of a phrase — the Mission's "say it" card, the scene's lines, Practise saying — goes to `POST /v1/speech/pronunciation-assess` with the phrase's server id and the mission's id as `scenarioId`, and the app shows the server's verdict on its **meaning**: *Understood!*, *Not quite* (with what it heard), or *I couldn't make that out* (the recognizer was unsure, never blamed). Never a pronunciation score (reference comparison only, ADR-006). A silent take is not sent; a check that fails falls back to comparing by ear. The take is sent inline and, unless the learner opted in to keeping recordings (said on screen), not kept. In a mission, a reply not understood on its first checked take goes to review as *hard*. **Answer out loud:** in a mission, the reply can be said instead of chosen (the options stay below as the fallback): understood is the reply given unaided (good in review), not understood keeps the options (hard). **Review:** the phrase said out loud is checked, the answer is revealed with the verdict, and the rating it suggests is highlighted (Good when understood, Again when not); the learner still chooses. |
| AI pronunciation feedback | Where takes are checked by the server (*Speech check*), a take of a phrase also offers **How did I sound?** (`lib/core/backend/pronunciation_coach.dart`): the take is decoded in the browser and resampled to 16 kHz mono WAV (`recorder_web.dart`, what listening models hear), then sent to `POST /v1/speech/pronunciation-feedback` with the phrase's server id. An audio-capable model on OpenRouter (Gemini Flash, `packages/ai/src/speech/pronunciation-judge.ts`) is asked for the phrase's expected IPA, then for what it hears sound by sound, *as if it did not know the target* (otherwise models "hear" the target), then to compare word by word, knowing the errors typical of the learner's first language. The panel shows its **estimate** out of 100 with a band (*Native-like*, *Clear, with an accent*, *Hard to understand*, *Not the phrase*), each word marked good / unclear / to work on / missing with a tip, the most useful thing to practise, and the expected vs heard sounds (IPA); tips are in the learner's instruction language. Said on screen to be an AI estimate; it never counts as progress, XP or mastery (ADR-006 still governs acoustic scores) and nothing is stored but the cost record. A silent take costs nothing (*no speech*). Probe of 2026-11-11: a native take 100, an English-accented one 62, a silent-h error 75 with the right tip, another language 0. |
| Live call (Talk stop) | Signed in, on a course whose snapshot has live conversation (`capabilities.liveConversation`), each mission path gets a fourth stop, **Talk**, and the mission's completion screen offers **Try it in a live call** (`/call/:mission`, `lib/features/call/`). Nothing starts until the learner taps **Call** (a call costs model calls): the phone rings, then the mission's character picks up through `/v1/ai/conversation/session` (mission scope: its goals and scene) and speaks their opening line. The caller is the art roster's clay portrait (`assets/characters`, mapped from the server's `characters.id`, a UUIDv5 of the roster id) in the mission's animated scene: their mouth follows the voice's level (`talking` ↔ `lip_sync` frames, the level read from Web Audio), rings swell with the voice, the expression changes with each line (greeting, follow-up question, confusion…) and a small reaction floats up. Subtitles highlight the words as the voice reaches them; **Translate** shows the server's gloss. The learner answers by voice (tap to talk, tap to send: the take goes inline to `/turn`, the server transcribes it and the bubble shows what it heard) or in writing; **Hint**, **Explain** (the server explains the character's last line in the learner's language), **Example** (another sentence using it, with a note) and **Slower** are the API's commands, each answer labelled as help; **Translate** shows the line's gloss and **Repeat** replays it on the device. Goals tick off as the server counts them (dots, when the mission's goals have no description in the learner's language). Turns are replay-safe (same `clientTurnId` on retry, 409 `turn_in_progress` waited out). Before the call, **Phrases you might need** lists the mission's own phrases (its discovery cards: script, reading aids, meaning, Listen); during it, the **Phrases** chip opens them over the call (text only, nothing plays over the call; no AI). Goals show by name (chips during the call, a "Goals met" list after it) now that the locale catalogs word them (`curriculum.objective.*`). **Hang up** shows the server's evaluation: goals met, its summary, at most two corrections ("Next time, try"), XP; without an evaluator nothing is claimed. A call hung up before the learner said anything shows a plain line instead of a summary (which would describe only the character's lines), and credits no stop. Without a recorder (or for a text-only course) the call is a written chat. Signed out, on a course whose characters can be called (the public catalog says so: `GET /v1/courses`), the path shows **Talk** locked ("A live call with Lucía: with a free account") and the mission's end offers **Practise it in a live call (free account)**: both open the account screen, where signing up is; nothing is called. |
| Speak tab | When live calls back the course, a **Speak** tab lists the course's characters (`GET /v1/courses/:track/manifest` → `characters`) with their roster portraits and their role in the interface language (the server's roles are English; `cast.json` in the bundle carries English and French roles for the shipped portraits, from `packages/locales` `cast.role.*`); tapping one opens the same call screen as a **free conversation** (`/talk/:character`: the session names the character and no mission, so there are no goals and no path stop is credited). The call happens where the character works or lives, read from the role in their roster id (café staff at the café, a coworker at the office, a bus driver on the bus, a neighbour at home…); for a role without one place (a student, a schoolboy) it is the learner's next mission's scene. Below the characters, **Recent calls** lists the learner's calls on this device (`lib/features/call/call_history.dart`, at most 20 per course, only calls where the learner said something): who, when, how long, goals met, corrections. A call's page (`/calls/:id`) has its goals, the server's summary, the corrections ("Next time, try", with the phone's voice where it has one: the server's voice reads approved course content only), the conversation (with the character's glosses), **Call again** and **Delete this call**. Kept on the device only; **Reset all progress** deletes it, with the Out-loud counts and the lessons heard. |
| Your data | Settings › Account › **Export my data** downloads the server's JSON bundle (`GET /v1/me/export`; web only for now — native needs a file/share plugin). **Delete my account** asks for a typed confirmation word, calls `DELETE /v1/me`, and signs out only once the server has answered (`deleted` / `scheduled`, shown as such); progress on the device stays until the learner resets it. |

Server ids are computed offline: missions and expressions are UUIDv5 of their curriculum keys
(`core/backend/curriculum_ids.dart`, same namespace as `packages/db/src/seed/curriculum-uuid.ts`). Every call is
idempotent (deterministic `clientAttemptId` / `clientEventId`), so an interrupted sync is simply run again.

Configuration — client-safe values only (URL, anon key), never a secret:

- native builds: `--dart-define=LQ_SUPABASE_URL=… --dart-define=LQ_SUPABASE_ANON_KEY=… --dart-define=LQ_API_BASE_URL=…`;
- the web image: Caddy fills `/config.json` (`deploy/config.json`, a template) from the container's environment on
  each request — `LQ_SUPABASE_URL`, `LQ_SUPABASE_ANON_KEY` (or the hosted app's `NEXT_PUBLIC_SUPABASE_URL` /
  `NEXT_PUBLIC_SUPABASE_ANON_KEY`) and `LQ_API_BASE_URL`; nothing is written at start-up. The API Worker needs its secrets and the web origin in `CORS_ALLOWED_ORIGINS`
  (`apps/api/wrangler.toml`, `infra/cloudflare/README.md`).

Email links (web): **Create account** asks the server to send the confirmation link back to this web app
(`emailRedirectTo` = the app's own address), and **Forgot password?** emails a link to choose a new password. When the
app is opened from such a link (`?code=…`, PKCE), `main()` signs in from it once, takes the code out of the address
bar before the router reads it, and says what happened: confirmed and signed in, a **Choose a new password** dialog
after a reset link (`updateUser`), or why a link cannot be used (expired, already used, or opened in another browser
than the one that asked for it, which holds the PKCE verifier). Checked end to end against the local stack, emails
read from Mailpit. For this to work on an instance, its auth settings must send email (SMTP) and accept the web
origin as a redirect: Site URL or *Additional redirect URLs* containing `https://web-languest.tayoo.app` — otherwise
GoTrue falls back to its Site URL (on the Infra Tayoo instance, still `http://localhost:3000`).

On the live web app (https://web-languest.tayoo.app › Settings › Account), sign in with the test learner whose
credentials are the hosted app's `LOCAL_LEARNER_EMAIL` / `LOCAL_LEARNER_PASSWORD` variables (confirmed on the
instance, no email needed). New accounts need email confirmation on that instance.

Try it locally (local stack and local test accounts only):

```bash
pnpm --filter @langquest/db local:start
pnpm --filter @langquest/scripts seed-languages && pnpm --filter @langquest/scripts seed-curriculum -- --apply
# apps/api/.dev.vars from .dev.vars.example with the keys of `pnpm supabase status -o json`, API_ENV=development
pnpm dev:api                                         # http://127.0.0.1:8787
docker build -t langquest-web . && docker run --rm --network host -e PORT=8090 \
  -e LQ_SUPABASE_URL=http://127.0.0.1:54321 -e LQ_SUPABASE_ANON_KEY=<local anon key> \
  -e LQ_API_BASE_URL=http://127.0.0.1:8787 langquest-web   # http://localhost:8090 › Settings › Account
```

## What the app does

| Area | How it works |
|---|---|
| First run | Choose the app language (English or French), then a course that can be taught from it. A course page lists what it **includes** and what it **does not have yet** (draft content, no dialect voice, no live conversation, no audio library) before enrolling — CONVENTIONS §8. |
| Courses | All 30 tracks in the catalog. Startable today (bundled drafts): Arabic (Moroccan) from French or English, Spanish (Spain) from English, Japanese from English, English from French. The rest show as *Planned*. One enrollment per track × instruction language; switch from Home's course chip. |
| Learn path (approved **L1 + L3 inside N2**) | Each mission is a node: **Learn** (L1 scene: the dialogue line by line, target script + romanization + meaning, the learner shadows their lines, the lines already heard staying above as the thread of the conversation; then L3 discovery cards, each with what the course says about the phrase: its words one by one (`literal`), when to use it, how to say it) → **Practise** (a session from recognising to producing: see *Practice session* below) → **Play** (a round of a mini-game with the mission's own phrases: see *Mini-games* below) → **Mission** (played as the conversation it is: the character's line arrives in a bubble, the learner chooses the taught reply, says it out loud, and the exchange joins the thread above). Everything a mission asks was taught in its own Learn stop. Missions unlock in order. The **Missions tab** is a walk through the course's places along a string of lanterns (`lib/features/missions/missions_screen.dart`): a lit lantern is a mission done, the glowing one is the next — shown with its place alive, its stops and the one to take — and the others wait, dimmed, behind a small still picture of their place; the chapter says how many missions are done. A **mission's page** lists its stops as numbered steps under its place, then *More ways to practise* (saying the phrases, the mission's audio lesson), each only where it can be used. Each mission happens in a painted place (`lib/features/scenes/scene_painter.dart`, picked from the mission's situation), with day and evening versions and a slow loop of life: steam rising from cups, curtains in the breeze, lanterns and pendant lamps swaying, scenery sliding past a carriage's windows, a plane taking off past the terminal's glass, copper lamps swaying in the souk, a station clock going round and its departure board flipping, petals falling in the park, string lights twinkling on a rooftop, candles flickering. All twelve places have their own drawing (café, street, airport, market, home, office, carriage, restaurant, rooftop, station, park, clinic); reduce motion holds them still. |
| Review | Phrases used in a mission enter spaced review (first try right = good, otherwise hard). Recall from the meaning, reveal, rate Again / Hard / Good / Easy. The scheduler is a Dart port of the API's FSRS-like scheduler with the same defaults; `test/srs_test.dart` checks it against vectors produced by the TypeScript implementation. |
| Progress | Only measured numbers: XP (practice, never proficiency — product XP amounts: mission 50, step 5, review 3, each mission paid once), streak from active days, this week, missions completed, phrases met / in review, and review strength from the schedule (not a speech score). Once there is any, **Out loud**: takes the server judged and how many it understood, live calls and their minutes, audio lessons heard to the end (`lib/core/services/speaking_stats.dart`). The XP the server awards for a call counts in the total, as the call summary says. Signed in, **What you can do** lists the skills the server has evidence for on this course (`GET /v1/me/skills`, `lib/core/backend/server_skills.dart`), strongest first: each skill's name (from the bundle's `skills.json`, English or French), its CEFR band, its step on the four-step ladder (emerging, practised, independent, durable) and the number of observations behind it; **How this is measured** explains the steps, and says a CEFR band describes the skill, not a certificate. Nothing measured yet says how to get there; a failed load says so and retries. Signed out, the section is absent. |
| Settings | Account (when a backend answers), app language, **display** (below), courses (switch, remove with confirmation), reset all progress (display choices stay), open-source licenses. |
| Display and accessibility | The Expo app's choices that apply here (`lib/features/account/display_settings.dart`, `lib/core/layout/display_preferences.dart`): theme — dark (default), light, or the device's, followed live; text size 90–180 % on top of the device's own, in steps (a slider's value bubble left an empty full-screen node in the web accessibility tree); reduce motion — scenes, Melo, slides and page transitions stand still, also when the device asks for it; show or hide Melo, who never carries information of its own. Every screen holds up at 200 % text on a 360 × 690 phone, and a whole mission node is walked at 200 % in the widget tests. Motion, where it is on: a mission completed, a call whose goals were met and an audio lesson heard to the end burst into confetti and count their XP up (`lib/core/layout/celebration.dart`); a wrong pick shakes and the right one pops; scene lines arrive from their speaker's side; a speaking character's badge pulses. All of it is decorative and absent with reduced motion. |
| Record and compare | On the learner's own lines (the Learn scene, the Mission's "say it" card), where the device can record — the web app today (`lib/core/platform/recorder_web.dart`): record yourself, then play your take next to the reference voice, ADR-006's *listen / record / compare*. No score or waveform, only the microphone level while recording; a take whose loudest moment stays at or below −50 dBFS (the server's silence floor, `SILENCE_PEAK_DBFS`) is answered "I didn't hear anything". A refused or missing microphone is said plainly, with **How to allow the microphone**: the steps for the learner's device (iPhone/iPad Safari: “aA” › Website Settings › Microphone; Android Chrome: the icon left of the address › Permissions › Microphone; a computer: the icon left of the address), since the browser remembers a refusal per site. In a call, a refused microphone keeps the call going in writing and says the same. Phone browsers record in their own format (Safari: AAC in MP4, sent as `m4a`; Chrome: WebM/Opus): both are transcribed by the server (checked live: “Hola, buenos días.” understood in each). Offline or signed out, the take stays in memory on the device and is dropped when the line changes; signed in, it is also checked by the server (*Speech check*, under Account). Without a recorder (the iOS and Android builds, no plugin yet) the control is not shown. |
| First-run warm-up | After the very first course is chosen (the Expo app's onboarding warm-up): **Try your first phrase** — the course's first taught phrase with its meaning, Listen when a voice exists, and Record yourself where the device can record. Nothing scored; **Start learning** opens Home. Later courses open Home directly. |
| Practise saying | Once a mission's Learn stop is done, its path offers **Practise saying the phrases** (`/speak/:mission`, where the device can record): each taught phrase big, with Listen / Slowly and Record yourself → My voice — the *listen / record / compare* coach of ADR-006, the offline counterpart of the Expo app's pronunciation coach. No score (no acoustic assessor) and no XP. |
| Voice | **Bundled natural AI voices first, for every learner** (signed in or not, offline too): every line of the bundled courses was read once by a Gemini TTS voice instructed with its variety (Castilian Spanish, Tokyo Japanese, Casablanca Darija, American English) and ships in `assets/audio/lines/` (2.2 MB; `assets/content/voices.json`, made by `pnpm --filter @langquest/scripts synthesize-bundle-audio`). The two sides of a dialogue sound different: each character is cast with their own voice (`SeedCharacter.voice`) and the learner's role has one voice per course that no character shares (so audio lessons are a real two-voice conversation). Each clip passed a blind listening check before it was kept (a listening model wrote down what it heard, then compared it with the line and rated naturalness; anything wrong or below 8/10 was synthesized again: 49 retakes, 168 of 170 lines kept; MAI-Voice's English voice was dropped, rated 5–6 "robotic"). **Slowly** plays the same clip at 0.72× with the pitch kept (asking a model to "speak slowly" barely did). A line without a bundled clip uses the server's AI voice (signed in; its English and Castilian defaults are now the same Gemini voices) and then the device's synthesizer, only for the exact locale (`es-ES` never falls back to a Latin American voice; no device voice for Darija). On the web the device voice's normal pace is the Web Speech rate 1 (it was 0.5, half speed, so "Slowly" barely differed). It is announced as "AI voice" to screen readers. |
| Read aloud | Exercises are read aloud as they appear (Settings › Display › **Read exercises aloud**, on by default; the speaker button beside a question reads it again): the **narrator** says the context and the question in the learner's instruction language, then the phrase is said in the course's voice. In a mission: the scene's context on the first exchange, "Karim says", the cue, "What do you answer?" (or "How do you say “…”?"); in the Learn scene: the context and "Your line — say it out loud" before the learner's lines; in review: the question, then the answer in the course's voice once shown; audio lessons are narrated by it too. Signed in, the narrator is an AI voice of the instruction language (`POST /v1/speech/narrate`, `lib/core/backend/narrator.dart`; the server only narrates in the enrollment's source language, never target-language content, so a narration is never a model to imitate); otherwise the device's voice for that language. The narration uses the app's words in the course's instruction language, whatever the interface language; a course taught from a language the app has no translation for is not narrated. Starting a recording, choosing a reply or moving on stops it. |
| Speaking steps | Where the device can record, a line to say (the Learn scene's own lines, the mission's "Say it out loud") waits for a take before **I said it**: a take the server understood, or any real take where nothing can check it (signed out), or three takes not understood (the line then goes to review as hard). **Can't speak now** pauses speaking steps for 15 minutes. Signed in, each take is checked for meaning and the AI's pronunciation feedback (score, each word, the tip) comes by itself, no tap needed; signed out on a course the server checks, the take offers **Have LangQuest check what you said: create a free account**. |
| Calls: Translate | First in a call's help row: **Translate** puts the character's last line, in the learner's instruction language, under that line (tap again to hide). The server's own gloss when it wrote one (nothing asked); otherwise the server is asked once (`translate` command) and its answer is attached to the line, which is not said again and not added as a new one (`CallSession.translateLast`). |
| Audio lessons: your turn | Where the device records (and speaking is not paused with **Can't speak now**), each "your turn" waits for the learner to say the phrase instead of a timed pause: a take, checked by the server where it can (understood, or 3 tries), then the lesson goes on by itself. **Next** and the transcript cannot skip past a turn that waits. Without a microphone, or paused, turns are the timed pauses they were. |
| Every course, from English and French | All 30 courses have two chapters. **Chapter 1** (7 missions, ~75 phrases): the four hand-authored drafts, and 26 drafted by `content-factory` (Claude Sonnet 5.5, from English) with the French learner text added from the target phrases (`import-factory-chapters`); Spanish and Japanese got their French the same way (`packages/curriculum/src/content/overlays/`), and every line of the four hand-authored chapters now has a note written for French speakers. **Chapter 2** ("settling in", 6 missions, ~65 lines: a meal, clothes, a train or coach ticket, asking for help, family, weekend plans) was written for each course in a compact format (`packages/curriculum/src/content/authored/chapter-2/*.json`, checked by `authored-check.ts`: every slot filled by its own line, the course's script and transliterations, French learner text written for French speakers — false friends, sounds described with French references — not translated from the English); its lines have no bundled AI clips yet, so they are said by the server's voice or the device's, and their audio lessons are offered only where one of those can say every line. The French course is offered from English; the English course from French (and Russian). Every chapter is an unreviewed AI draft (the course page says so); scripts and transliterations are checked per course (Cyrillic, Greek, Hebrew + niqqud, Devanagari, Hangul, Han with pinyin/jyutping, Arabic with a Latin transliteration). |
| Practice session | The Practise stop is a session built from the mission's own phrases (`lib/features/learn/practice_session.dart`, pure and deterministic; `practice_screen.dart`), going from recognising to producing so each phrase is met several times in different ways: two questions about **earlier missions** first (what was learned before comes back); the first **pairs**, then the phrases just matched by ear (**Listen. What does it mean?**, read instead when nothing can say it) and as **Is this what it means?** (yes / no); the other pairs, then **Which one says this?** (a meaning; choose the phrase) and **Listen. Which one did you hear?** (among three written phrases, only where a voice can say it); **Complete the sentence** (two of them); **Build the sentence** from its meaning, then another **from what is heard**; and, in Latin-script courses, **Write this phrase** (case and punctuation never count; missing accents or one slip of the finger are accepted and pointed out). One answer per question: a panel says how it went and shows the phrase with its meaning and its voice; a question missed **comes back once at the end** (*Once more*). A sentence to build is worked on until it is right, each word showing whether it is in its place after a check. No score: the last screen says how many were right the first time and lists the phrases *worth another look*, then leads to the mission. Questions by ear use the bundled clips at once, without waiting for the device's own voice list (`lineVoiceNowProvider`). |
| AI models (admin) | Signed in as an admin (`GET /v1/me` roles `admin` / `super_admin`), Account shows **AI models (admin)** (`/admin/models`): each task the AI does in plain words, the model that does it then its fallbacks, for every course or one variety, built-in or changed by an admin. **Change** picks the scope, the model (suggested from the router's live catalogue), the fallbacks and, for the server voice, a voice of that variety; **Test and save** goes through `PUT /v1/admin/models/:task/config`, which runs the task's smoke tests first and refuses a change that fails them. The Worker routes by the change within its profile cache (about a minute). The AI pronunciation listener is its own task (`pronunciation_feedback`); the voice-call pipeline and the acoustic pronunciation assessor (Azure, ADR-006) are shown but not changeable. The bundled course clips are made offline (`synthesize-bundle-audio`), not by this setting. |
| Real examples | On a phrase card (Learn) and in Practise saying, **Real examples** (shown only when there is something the learner can read) opens a sheet of real sentences from **Tatoeba**, the spec's first source (§9.1–9.2): whether the phrase is itself a sentence written by a Tatoeba contributor ("people really say it this way"), up to two short sentences using it with their translation in the learner's instruction language, and native recordings where the recording's own license allows it (CC BY / CC BY-SA / CC0; bundled in `assets/audio/tatoeba/`, played from the app, never NC or unlicensed audio). Each sentence is credited (`Tatoeba #id by contributor`), each recording with its contributor and license, and the sheet credits the export (CC BY 2.0 FR, export date). Spanish examples say that Tatoeba does not record the country. Built by `pnpm --filter @langquest/scripts attach-tatoeba-examples -- --dir data/raw/tatoeba` (`assets/content/examples.json`, the SHA-256 of every input recorded): 80 of the 170 phrases have examples, 64 are attested as written; 4 licensed recordings (English). Evidence of real use, not a substitute for native review of the course's own lines (`docs/content-rights/dataset-attribution-inventory.md`, row 1b). |
| Audio lessons (Audio tab) | One lesson per mission, made on the device from what the mission teaches (`lib/features/audio/`), in **four parts**: *Listen* (the conversation line by line), *Repeat* (phrase by phrase: the meaning, the phrase slowly, time to say it with a countdown, the phrase again), *Recall* (from memory: "How do you say …?", time to say it, then the phrase — every phrase, in another order than taught) and *Your part* (the conversation again, the character's lines said and the learner's left to the learner, each cued by its meaning and then said to check; only when the mission has a character to answer). Two **mixes** made from the whole course sit above the lessons: **Every conversation** (all of them back to back, listening only) and, once a mission's Learn stop is done, **Recall workout** (up to 14 phrases of the missions learned, mixed, asked from memory; the order changes as more is learned). Lines are read by the course's voice (device or AI), the narration by the device's voice for the learner's language when it has one (else shown as captions). The player shows the line being said big with its meaning in the mission's scene (a mix moves from place to place), the parts, how much is left, a transcript to jump around in, previous / play-pause / next, *Slowly* and *Time to repeat* toggles, and prefetches the next lines from the server. A phrase asked from memory is not written — on the card or in the transcript — until it has been said. A lesson heard to the end is marked listened (on the device). The Audio tab exists only when the course's lines can be heard here. |
| Mini-games | Another way to meet the phrases already taught (`lib/features/games/`): the games play only with phrases of missions whose Learn stop is done (teach before test), one per text and per meaning, and open once there are four. They live in two places. The **Play tab** (`/play`) holds them with every phrase learned (a **Mini-games** card on Home and a link after a mission lead there); before anything is taught, the tab says what the games are played with and opens the first lesson — never a dead end. And every mission has a **Play step** between Practise and Mission (`/learn/<mission>/play`): a round with that mission's phrases only, the warm-up for its conversation. The games take turns from mission to mission (Lantern pairs, Quick fire, Sentence dash, By ear), each only where the mission has enough for it (`missionGameFor`, `gamesPlayableWith`); the round ends on *Start the mission*, completes the step (+5 XP the first time, like every step) and keeps no record, its phrases being its own. **Lantern pairs** (memory: every phrase and its meaning hide under the lanterns; a phrase is said when turned; what counts is the moves), **Quick fire** (a phrase and a meaning: yes or no? as many as possible in 45 seconds, 30 in a mission's round; a wrong answer stops the clock and shows the meaning), **By ear** (a phrase is said: find it among four written ones, eight times; listed only where the phrases can be said) and **Sentence dash** (put the words of each sentence back in order, one intruder among them, against the clock; listed only with three sentences long enough). Rounds are drawn from a seed (the number of rounds played), so every round differs and tests are exact (`game_logic.dart`). Records stay on the device per course and game (`GameStats`: fewest moves or seconds, most right answers) and are forgotten with **Reset all progress**. A round played to the end pays 5 XP once a day per game (XP measures practice; a game is practice). Nothing here is a proficiency score. |
