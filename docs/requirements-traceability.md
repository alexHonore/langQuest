**Conventions used in this file**

- `implemented_tested` is claimed only when the code exists **and** a passing test or captured evidence covers the row (the Evidence column names it). Logic-level tests count for behaviour; device-only behaviour (background audio, mic prompts, RTL restart) does not count as tested until a development build runs.
- `in_progress` means code exists but is partial, or exists without a test/evidence; the Evidence column says what exists and what is missing.
- `blocked_by_external_dependency` is used only where nothing further can be done locally without an owner action listed below (R2 not enabled, hosted Supabase slot, Azure key, native-speaker review, licensed audio, device QA requiring a development build, rights-holder permission). Rows that can still be advanced locally keep `in_progress`/`not_started` with the dependency named in the Blocker column.
- Content rows are honest about volume: the spec target is ~40 missions / ~800 expressions per track with reference audio; today the best track (arabic-moroccan) has 6 published **draft** missions and 49 seed + 56 JSONL draft expressions, 0 native-reviewed, 0 with audio; 26 tracks have chapter-1 skeletons only (see `docs/evidence/test-run-2026-10-19.md` §5).
- Evidence is a repo path (code, migration, test, screenshot, doc). `—` means none yet.
