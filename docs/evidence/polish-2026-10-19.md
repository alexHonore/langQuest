## 2. How the screenshots were produced (no desktop browser pane)

- `apps/mobile/dist` served on `127.0.0.1:8921` by `python3 -m http.server`'s handler subclassed so unknown paths fall
  back to `index.html` (Expo web `output: "single"` is client-routed; plain `http.server` would 404 on `/onboarding/welcome`).
  Script: `docs/evidence/tools/polish-capture/spa_server.py`.
- Headless Chrome (`/Applications/Google Chrome.app/Contents/MacOS/Google Chrome --headless=new`, 430×932 device
  metrics at 2× scale) driven over the DevTools protocol by `docs/evidence/tools/polish-capture/cdp-shots.mjs`
  (Node 24, no extra dependencies). Plain `--screenshot=` cannot preload a session or preferences, so the driver
  primes `localStorage` on the origin first, then navigates, waits for the rendered text to settle, screenshots, and
  reads the DOM for the density audit. Console errors and uncaught exceptions are recorded per screen.
- Session: a sign-in token for `learner-local@langquest.test` was minted with the local stack's password grant and
  injected as supabase-js's `localStorage` entry (`sb-127-auth-token`); learner preferences (`langquest:prefs`,
  scheme `dark` / `light`, onboarding state, pending course) were injected the same way. The learner had no enrollment
  left after the test-hygiene teardown, so it was enrolled in Arabic (Moroccan) from French through the local API
  (`POST /v1/me/enrollments`) before the authed captures. Tokens live only in the session scratchpad; nothing was
  written to the repository.
- Admin: the production build was started on `127.0.0.1:3011` (`next start`), the `admin-local` session was minted
  the same way and set as the chunked `@supabase/ssr` cookie (`base64-…`, 3,180-char chunks); the Studio scheme
  (`lq_admin_theme` in `localStorage`) was primed to `dark` / `light`.
- Before/after baseline: `HEAD` (`9b3693e`) was checked out in a throw-away git worktree, exported for web the same
  way and served on `127.0.0.1:8922`; the same scenarios and the same DOM measurement ran against it.
  Config generator: `docs/evidence/tools/polish-capture/make-config.py`; raw audits:
  `audit-before-mobile-2026-10-19.json`, `audit-after-mobile-2026-10-19.json`, `audit-after-admin-2026-10-19.json`.

## 3. Regressions found by the run and fixed (real fixes, all re-verified)

| Where | Symptom | Cause | Fix |
|---|---|---|---|
| `apps/mobile/src/app/(tabs)/index.tsx` (Home) | Home rendered a **blank white page** on web (0 words, uncaught `TypeError: Cannot read properties of null (reading 'scriptMode')`). Vitest did not catch it (tests run without the React Compiler). | The polish pass lifted the conversation CTA into a render-scope closure using `enrollment!.id`. The React Compiler treats that unconditional load as proof that `enrollment` is non-null and compiles the `useEffect` deps as `q.scriptMode` (optional chain dropped), which throws while `/v1/me` is still loading. | Replaced the non-null assertion with a real guard (`if (!enrollment) return;`). Home now renders (48 words, "Bon retour, Alex Test !"), screenshots `polish-home-*.png`. |
| `packages/ui/src/components/Lanterns.tsx` | The U2 lanterns rendered as **flat opaque discs** instead of glows (`theme.lanterns.blur` was computed but never applied). | The `Blob` used `blur` only to pick the fallback scale/opacity; no filter was ever set. | On web the blur is now a real `filter: blur(Npx)` (react-native-web passes it through; verified); native keeps the enlarged/fainter solid-tier fallback (iOS has no blur filter). Visible in every `polish-*-dark.png`. |
| `apps/mobile/src/app/catalog/[trackId].tsx`, `apps/mobile/src/app/onboarding/target.tsx` | The dialect disambiguation (`≠ Modern Standard Arabic, Egyptian Arabic, Levantine …`) was one **chip overflowing the screen edge** (HEAD rendered it as wrapping text). | A single `Chip` with the joined list cannot wrap. | One chip per variety in a wrapping `Row` (same pattern `onboarding/confirm.tsx` already used). See `polish-course-arabic-moroccan-*.png`, `polish-onboarding-target-*.png`. |

Not a working-tree regression (baseline only): the HEAD build's Speak tab throws `Unknown character: ary-student-omar`
because the database cast was re-seeded for the C2 cast (migration 140) and HEAD's code predates those ids — so the
baseline has no Speak measurement.

## 6. What could not be captured / caveats

- **Rive / motion**: static screenshots only; lantern drift, Melo state transitions and reduced-motion variants are not
  evidenced here.
- **Lantern colour change per lesson**: course-level tint is visible (Darija brick/teal on catalog, Home, Missions,
  Speak; onboarding uses the neutral plum/teal/amber set). A lesson in progress (mission / conversation screens) was
  not screenshotted because those flows need a live model call or microphone; the lesson-type modulation is covered by
  the `packages/ui` token tests (327 passing), not by a screenshot.
- **Native**: iOS / Android builds were not run; on native the lantern glow uses the solid-tier fallback (no blur
  filter) by design.
- **Admin dark vs light**: both captured by priming `lq_admin_theme`; the admin does not follow
  `prefers-color-scheme` unless the preference is `system`.
- **HEAD baseline Speak**: not measurable (see §3).
- `polish-home-check.png` in the screenshots folder was not produced by this run.
