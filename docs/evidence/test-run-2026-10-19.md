## 3. What this run does not cover

- **Live provider tests (OpenRouter).** `packages/ai/src/live/live.test.ts` (4 tests), `apps/jobs/src/__tests__/live-transcribe.test.ts`
  (1) and `apps/api/src/__tests__/live/conversation.test.ts` (1) were run by the builders during the build sessions
  (2026-10-14 capability smoke, 2026-10-15 content factory, 2026-10-19 adversarial review) with a total spend of about
  **$0.10** across all live calls (the 2026-10-14 smoke alone was ≈ $0.004, the Darija chapter draft ≈ $0.022). They were
  not re-run for this evidence file; `docs/provider-matrix/ai-capability-matrix.md` records what those calls verified.
- **Azure Speech** was never exercised (no `AZURE_SPEECH_KEY`); the adapter is covered by fixture tests only.
- **Deployed Worker.** `https://langquest-api.langquest-nsh.workers.dev` is deployed but answers every request with
  `HTTP 503` and the body
  `{"ok":false,"error":{"code":"provider_unavailable","message":"API is not configured yet (missing or invalid Worker secrets). See infra/cloudflare/README.md.","details":{"reason":"[ … \"path\": [\"SUPABASE_URL\"] … \"path\": [\"SUPABASE_ANON_KEY\"] … "}}}`
  (checked with `curl …/healthz` on 2026-10-19). It will keep doing so, by design (fail closed), until the hosted
  Supabase project exists (`B-SUPABASE`) and the secrets listed in `infra/cloudflare/README.md` are set with
  `wrangler secret put`. All API verification therefore happened in-process against the local stack (HS256 JWTs);
  ES256/JWKS verification is covered by a unit test with a generated key pair, not against a hosted project.
- **Cloudflare R2** is not enabled on the account: every presigned URL / multipart / prefix-import / public-bucket path is
  exercised only through the in-memory fake server (`apps/admin/src/lib/upload/engine.test.ts`) and the dev-only
  `LocalFsObjectStore` (`apps/jobs/src/r2.ts`); the API answers `capability_unsupported` for those endpoints and the
  tests assert that honest refusal.
- **Mobile on a device / simulator.** No development build was produced; `tests/e2e/maestro/*.yaml` (8 flows) were not
  executed; expo-audio background playback, lock-screen controls, microphone prompts and the RTL restart are verified
  by logic tests and the web export only (`docs/provider-matrix/mobile-audio-qa.md`).
- **Admin Playwright e2e** (3 specs) and the **load script** (`tests/load/run-load.ts`) were not run.
- `pnpm lint` was not part of the requested run.
