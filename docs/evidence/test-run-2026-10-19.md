  `HTTP 503` and the body
  `{"ok":false,"error":{"code":"provider_unavailable","message":"API is not configured yet (missing or invalid Worker secrets). See infra/cloudflare/README.md.","details":{"reason":"[ … \"path\": [\"SUPABASE_URL\"] … \"path\": [\"SUPABASE_ANON_KEY\"] … "}}}`

  Supabase project exists (`B-SUPABASE`) and the secrets listed in `infra/cloudflare/README.md` are set with
  `wrangler secret put`. All API verification therefore happened in-process against the local stack (HS256 JWTs);
  ES256/JWKS verification is covered by a unit test with a generated key pair, not against a hosted project.

  exercised only through the in-memory fake server (`apps/admin/src/lib/upload/engine.test.ts`) and the dev-only
  `LocalFsObjectStore` (`apps/jobs/src/r2.ts`); the API answers `capability_unsupported` for those endpoints and the
  tests assert that honest refusal.
- **Mobile on a device / simulator.** No development build was produced; `tests/e2e/maestro/*.yaml` (8 flows) were not
  executed; expo-audio background playback, lock-screen controls, microphone prompts and the RTL restart are verified
